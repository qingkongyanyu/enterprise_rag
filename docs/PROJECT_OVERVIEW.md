# 项目介绍：企业私有知识库 RAG 智能问答系统

> 面试用项目文档。建议结合代码与演示页面讲述。

## 一、项目背景

企业内部有大量制度、流程、产品、财务类文档，员工查找效率低，且散落在各处。需要一个能**用自然语言提问、秒回精准答案并给出出处**的智能问答系统，同时要求：

- **数据安全**：文档与索引全量私有化部署，不出内网。
- **回答可溯源**：答案必须标注来源，不能凭空编造（企业场景的硬性合规要求）。
- **可运维**：非技术员工也能自行上传文档、维护知识库。

## 二、我的职责（独立完成）

- **全栈实现**：后端 RAG 管线 + FastAPI 服务层 + Vue 3 前端 + 文档 + Docker 部署。
- **RAG 调优**：分块策略、混合检索、重排、缓存等多环节优化。
- **工程化**：分层架构、统一异常、单元测试（27 个用例）、CI 友好的文档与部署。

## 三、技术方案

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite + Pinia | 深色科技风 SPA；SSE 流式打字机效果；来源引用卡片 |

## 四、核心难点与解决方案

### 难点 1：单一路径检索召回不全面

**问题**：纯向量检索对精确编号、人名、型号召回弱；纯关键词检索无语义泛化。

**方案**：**混合检索 + 倒数排名融合（RRF）**
- 稠密路径：FAISS 余弦 topK；
- 稀疏路径：BM25（jieba 分词）topK；
- 两路排名按 `score = Σ 1/(k+rank)` 融合，无需调权重、鲁棒性好。

**效果**：既能答「差旅住宿标准是多少？」（语义），也能精确命中「报销单号 BX-2026-0042」这类精确查询。

### 难点 2：检索质量取决于分块

**问题**：固定字符数硬切会劈断句子，语义丢失。

**方案**：**中文句读边界感知的递归分块**
- 优先段落边界 → 再按 `。！？；` 句读符切分，保证句子完整；
- 相邻块 64 字符重叠，避免跨块语义断档；
- 空块/超短块过滤，避免污染索引。

### 难点 3：RAG 回答必须可溯源、不编造

**方案**：**引用溯源 + 强约束 Prompt**
- 每个分块携带 `chunk_id + source`，Prompt 要求模型标注 `[n]`；
- 检索为空时**不调用 LLM**，直接返回兜底语（杜绝胡编 + 省 token）；
- 前端把来源渲染为可点击卡片，展示命中片段与匹配度。

### 难点 4：性能

**问题**：旧版每次请求重新加载向量索引，慢且不稳定。

**方案**：
- **索引常驻内存**（lifespan 单例 + 懒加载）→ 检索零加载开销；
- **嵌入磁盘缓存**（md5 为 key）→ 重建索引从 52s 降到 <1s；
- **响应命中缓存** → 重复问题 2ms 返回；
- **SSE 流式** → 首 token 即反馈，观感大幅提升。

### 难点 5：密钥安全与可复现

**问题**：初版把 API Key 硬编码在配置里，无法公开。

**方案**：pydantic-settings + `.env` 统一管理密钥，`.gitignore` 拦截；提供 `.env.example` 模板；`docker compose up` 一条命令复现；前端构建产物入库，clone 后仅需 Python 即可运行。

### 难点 6：前端体验

初版为单 HTML + 静态 JS。完全重构为 Vue 3 工程化 SPA：会话管理、流式渲染、来源卡片、知识库可视化操作、系统状态面板，统一深色科技设计系统（CSS 变量 + 玻璃拟态 + 渐变光效）。

## 六、可以深入的追问

1. **为什么 RRF 而不是加权求和**？—— RRF 对排名而非分数加权，无需标定两路量纲，实现简单且鲁棒。
2. **为什么自实现 BM25 而不用现成库**？—— 核心逻辑约 40 行，完全可控可测，也能体现对检索原理的理解。
3. **为什么不用 LangChain**？—— 规避版本断裂，核心逻辑自己掌控，代码可单测、可讲清。
4. **如何保证不编造**？—— 检索空短路 + 强约束 Prompt + 引用溯源三重保障。
5. **可扩展性**？—— 查询改写、语义缓存、增量索引、GPU 重排都是预留的演进方向（见 RAG_OPTIMIZATION.md）。
