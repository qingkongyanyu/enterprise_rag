# RAG 调优实践

本项目的 RAG 效果来自多个环节的协同调优。本文按「检索质量」与「性能」两条线说明。

## 一、检索质量

### 1. 分块策略（`services/chunking.py`）

分块质量直接决定召回上限。常见错误：按固定字符数硬切，把一句话劈成两半，语义丢失。

本实现：
- **句读边界优先**：优先在段落（空行）边界切分；超长段落再按 `。！？；\n` 句读符切分，保证句子完整。
- **重叠窗口**：相邻块带 `overlap`（默认 64 字符），跨块语义不丢失。
- **过滤无价值块**：长度 < 10 的碎片直接丢弃，避免污染索引。
- **元数据携带**：每块带 `source / category / title`，支撑引用溯源。

> 分块参数（`CHUNK_SIZE=512, CHUNK_OVERLAP=64`）在 `.env` 可调。

### 2. 混合检索（`services/retriever.py`）

**单一检索方式的短板：**

| 方式 | 擅长 | 短板 |
| --- | --- | --- |
| 稠密（向量） | 语义相似、同义改写 | 精确编号/人名/术语召回弱 |
| 稀疏（BM25） | 精确词、编号、专有名词 | 无语义泛化 |

**本实现：**

```
query → FAISS 余弦 topK   ┐
        BM25（jieba 分词）topK ┘ → RRF 融合 → Top-N
```

- **稠密**：`IndexFlatIP` + 归一化向量 = 余弦相似度；`bge-small-zh` 查询侧加官方指令前缀 `为这个句子生成表示以用于检索相关文章：`，检索效果更佳。
- **稀疏**：自实现 BM25（k1=1.5, b=0.75），配合 jieba 中文分词。
- **RRF 融合**：`score = Σ 1/(k + rank)`（k=60），对两路排名取倒数融合，无需调权重，鲁棒性好。

### 3. 可选重排（`services/reranker.py`）

融合后可用 `bge-reranker-v2-m3` 交叉编码器对 Top-N 精排，进一步提升精度。代价是慢一个量级，故默认关闭（`ENABLE_RERANK=False`），CPU 环境推荐关闭，GPU 环境可按需开启。

### 4. 引用溯源

每块携带 `chunk_id + source`，Prompt 要求模型在关键结论句末标注 `[n]`；返回结构带 `sources[]`（来源、匹配度、命中片段），前端渲染为可读的来源卡片——**回答可核验，这是企业级 RAG 的硬要求**。

### 5. 无命中短路

检索为空时**不调用 LLM**，直接返回兜底语「当前知识库中未找到相关资料」——既避免模型胡编，也省 token、省时间。

## 二、性能优化

### 1. 索引常驻内存

旧版每次请求都重新从磁盘加载 FAISS；本项目在 `lifespan` 中加载一次、常驻内存。这是最大的性能提升点。

### 2. 嵌入磁盘缓存（`utils/cache.py`）

以内容 md5 为 key 落盘缓存向量。效果：重建索引时已计算的块不再重复嵌入，第二次构建近乎瞬时。

```
第一次构建：20 文档 → 22 块，耗时 ~52s（含模型加载）
第二次构建：缓存命中 22/22，耗时 <1s
```

### 3. 响应命中缓存

相同问题（且无会话历史时）命中 `TTLCache`，直接返回缓存结果，实测重复提问耗时从秒级降至 **2ms**。

### 4. 流式输出

SSE 逐 token 输出，首 token 延迟即感知速度；同步生成器交由 Starlette 线程池迭代，不阻塞事件循环。

### 5. CPU 阻塞操作隔离

FastAPI 同步端点自动运行在线程池；重排、检索等 CPU 密集操作不会卡住事件循环。

## 三、Prompt 工程

系统提示词明确约束（`services/pipeline.py`）：

1. **只依据检索资料作答，禁止用模型常识编造**——这是 RAG 与普通 Chat 的本质区别。
2. 资料充分时正常作答并标注 `[n]` 引用；资料不足时如实说「未找到」，绝不强行编造。
3. 流程/制度类问题按「流程步骤 → 条件 → 注意事项」结构化作答，贴合企业员工使用场景。
4. 注入最近 N 轮会话记忆，支持多轮追问（如「再详细说说第二步」）。

## 四、可继续优化的方向

| 方向 | 说明 |
| --- | --- |
| 查询改写 | 用 LLM 把问题改写为 2-3 个子查询（多查询检索）提升召回 |
| 语义缓存 | 对问题向量化，近邻命中直接复用答案，进一步降本 |
| 段落重排 | 引入更重但更准的 reranker（GPU） |
| 增量索引 | 按文档粒度增量更新，而非全量重建（当前已按需重建） |
| 混合分块 | 按标题层级（Markdown 结构）感知分块 |
